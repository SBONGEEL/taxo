# TAXO — الخلفية وتطبيق الراكب (المراحل 1–9)

المرجع الوحيد للمشروع هو [SPEC.md](SPEC.md). هذا الملف يشرح تشغيل ما أُنجز من
القسم 16:

- **المرحلة 1:** البنية التحتية + هيكل FastAPI + Alembic + جداول
  `users`/`drivers`/`vehicles` + المصادقة بهاتف وكلمة مرور مع JWT.
- **المرحلة 2:** الإعدادات per-country (`pricing_rules`, `feature_flags`,
  `commission_settings`, `subscription_plans`) + جدول `provider_credentials`
  المشفّر مع CRUD إداري وseed لتوكنات Mapbox وTelr Sandbox + `GET /config`.
- **المرحلة 3:** جدول `rides` + التسعير عبر Mapbox Directions من الخلفية حصراً
  + endpoints الطلب والانتقالات بين الحالات.
- **المرحلة 4:** حضور الكباتن على Redis GEO + خوارزمية التوزيع (الأقرب أولاً،
  مهلة 20 ثانية، 5 محاولات أو دقيقتان) + مقابس WebSocket للتتبع والأحداث +
  مراقبة انقطاع الكبتن أثناء الرحلة.
- **المرحلة 5:** دفتر `wallet_transactions` غير القابل للتعديل (الرصيد مشتقٌّ
  منه، لا عمود رصيد) + شحن الراكب والتحويل P2P + محفظة الكبتن والسحب.
- **المرحلة 6-أ:** `payments` بالكاش وكليك اليدوي والمحفظة و**الدفع المختلط** +
  النزاعات وفصلها من اللوحة + `ride_route_points` وإعادة حساب `final_fare` على
  المسافة الفعلية + `ratings`.
- **المرحلة 6-ب:** تكامل **Telr** — `provider_orders` + صفحة الدفع المستضافة +
  webhook مع تحقق التوقيع + شحن المحفظة بالبطاقة فورياً + `saved_cards`
  بالـ tokenization والدفع بضغطة + الاسترداد عبر المزود.

  بيانات Telr Sandbox لم تتوفر بعد، فالمرحلة تعمل على **مزود وهمي** يُدار من
  عقد Telr نفسه (`TELR_USE_MOCK=true` في `.env.local`، أو حقل «مزود وهمي» من
  صفحة العقود). يُتجاهل في الإنتاج. لتجربة الدورة كاملةً محلياً:

  ```bash
  # 1) ادفع بالبطاقة  → يعود card_order فيه cart_id و redirect_url
  POST /api/v1/rides/{ride_id}/payments  {"method":"card","idempotency_key":"..."}
  # 2) حاكِ ضغطة الدافع على صفحة المزود
  POST /api/v1/payments/card/mock/{cart_id}  {"outcome":"paid"}   # أو declined
  # 3) أو دع الإشعار يسوّيها كما يفعل المزود
  POST /api/v1/payments/card/webhook  (form: tran_store, tran_cartid, tran_ref, tran_check)
  ```

  عند وصول بيانات Sandbox: أدخلها من صفحة العقود وأطفئ «مزود وهمي» — لا يُعدَّل
  أيُّ endpoint. وراجع الثوابت الثلاثة المُعلَّمة في رأس
  `app/services/card_gateway/telr.py` بالتوثيق الرسمي قبل أول تشغيل حقيقي.
- **المرحلة 7:** اشتراكات الكباتن — `driver_subscriptions` + الشراء بالقنوات
  الأربع (المحفظة والبطاقة من تطبيق الكبتن فوريتين، والكاش وكليك تسجيلاً من
  اللوحة بعد قبض المال) + **شرط الاشتراك الساري في التوزيع** وخريطة الراكب
  معاً + مهمة Celery دورية تعلّم المنتهي وتُخرج صاحبه من التوزيع وتنبّه قبل
  الانتهاء بأربع وعشرين ساعة.

  ```bash
  GET  /api/v1/subscriptions/plans           # خطط بلد الكبتن المفعّلة
  GET  /api/v1/subscriptions/me              # الحالة + الأيام المتبقية + الخطط
  POST /api/v1/subscriptions                 {"plan_id":"...","idempotency_key":"..."}
  POST /api/v1/subscriptions/card            {"plan_id":"..."}   # يعيد redirect_url
  POST /api/v1/admin/subscriptions           {"driver_id":"...","plan_id":"...","method":"cash"}
  ```
- **المرحلة 8:** صفحة العقود الكاملة (بطاقة لكل مزود + **اختبار اتصال** بلا أثر
  + تقنيع القيم) + واجهات مزود موحّدة بمزودين وهميين (`sms`, `push`, `cliq`,
  `payout`) + التكاملات الأربعة: **التحقق من الهاتف** (Firebase أو مزود SMS —
  والدخول كلمةُ مرور دائماً)، و**Push** عبر FCM مع جدول الأجهزة وحملات
  الإشعارات وساعات الهدوء، و**كليك الآلي** لشحن المحفظة، و**payout** للسحوبات.
- **المرحلة 9:** [`customer-app/`](customer-app/README.md) — تطبيق الراكب
  (PWA) بشاشات القسم 11 كاملةً على المسارات القائمة، ومنها **صفحة دفع كليك
  داخل التطبيق**. وأضافت للخلفية ما كانت تنتظره تلك الصفحة: ترحيلة `0013`
  بحقول كليك على `payments` (alias المعروض، والمرجع الداخلي، ومرجع الحوالة
  وزمنه)، و`services/cliq_qr.py` الذي يبني حمولة الرمز، و
  `POST /payments/{id}/cliq-reference` بإشعارٍ فوري للكبتن.

  ```bash
  # الراكب يحوّل ثم يُدخل مرجع حوالته — يُسجَّل مرةً واحدة ولا يُعدَّل
  POST /api/v1/rides/{ride_id}/payments        {"method":"cliq","idempotency_key":"..."}
  #   → يعيد cliq_charge: alias والمبلغ والمرجع وqr_payload وdeep_link
  POST /api/v1/payments/{payment_id}/cliq-reference  {"transfer_reference":"FT24..."}
  ```

## المتطلبات

Docker Desktop فقط. (المنافذ: 5432 لقاعدة البيانات، 6379 لـ Redis، **8001**
للـ API، **5173** لتطبيق الراكب، **5174** لتطبيق الكبتن، **5175** للوحة
الإدارة.) ولتشغيل الواجهات خارج الحاويات: Node 22+.

وإن كان **5173 مشغولاً** على جهازك بشيءٍ آخر، ضع `CUSTOMER_APP_PORT=5176` في
`.env.local` وأعد `docker compose up -d customer-app`. و**5176 وحده** هو البديل
المسموح في `settings.cors_origins` — أيُّ رقمٍ سواه يُردّ بخطأ CORS. وتبقى عودةُ
صفحة الدفع (`card_return_url`) على 5173، فاختبارُ قناة البطاقة يحتاج المنفذ الأصلي.

## التشغيل

```bash
cp .env.example .env.local   # ثم املأ القيم — الملف موجود مسبقاً ومعبّأ محلياً
docker compose up -d --build
```

عند الإقلاع يشغّل الحاوية `alembic upgrade head` تلقائياً ثم uvicorn، وترتفع معها
خدمتا Celery: `worker` للمهام و`beat` للجدولة (**نسخة واحدة من `beat` لا غير** —
نسختان تُطلقان كل دورة مرتين)، وحاوية `customer-app` بخادم Vite.

- فحص الصحة: <http://127.0.0.1:8001/health>
- توثيق تفاعلي: <http://127.0.0.1:8001/docs>
- تطبيق الراكب: <http://127.0.0.1:5173> · تطبيق الكبتن: <http://127.0.0.1:5174>
- لوحة الإدارة: <http://127.0.0.1:5175>

**المنافذ ليست اختيارية**: الثلاثة أصولُ CORS المسموح بها في الخلفية، وعليها
تُبنى عناوينُ العودة من صفحة الدفع المستضافة (`CARD_RETURN_URL` للراكب و
`CARD_RETURN_URL_DRIVER` للكبتن).

> **و`127.0.0.1` لا `localhost`.** على بعض أجهزة التطوير — ويندوز خاصةً —
> يُحلّ `localhost` إلى `::1` بينما تنشر Docker المنافذَ على IPv4 وحده، فيفشل
> النداء بخطأ يبدو عطلاً في الواجهة وهو عطلُ اسمٍ لا أكثر. والاسمان مسموحان
> في `cors_origins` معاً، لكن `127.0.0.1` هو الطريق المضمون. وإن استعملتَ
> `localhost` فاستعمله في **الصفحة والـ API معاً**: صفحةٌ على أحدهما تنادي
> الآخر نداءٌ عابرُ أصل يرفضه المتصفح.

### بذر إعدادات التطوير

```bash
docker compose run --rm --no-deps \
  -e DATABASE_URL="postgresql+asyncpg://taxo:taxo@db:5432/taxo" \
  -e REDIS_URL="redis://redis:6379/0" \
  backend python -m scripts.seed
```

يملأ إعدادات ليبيا والأردن (تسعير، مفاتيح ميزات، عمولة صفر معطّلة، خطط اشتراك)،
ويكتب توكنات Mapbox وTelr Sandbox **مشفّرة** في `provider_credentials` قارئاً
إياها من `.env.local` لمرة واحدة، وينشئ حساب المشرف الأول من
`BOOTSTRAP_ADMIN_PHONE`/`BOOTSTRAP_ADMIN_PASSWORD` (خارج بيئة الإنتاج فقط).
السكربت idempotent ولا يلمس أي صف موجود.

## الأسرار

- `.env.local` يحوي **أسرار البنية التحتية فقط** (DB, Redis, JWT, مفتاح
  `CREDENTIALS_ENCRYPTION_KEY`) وهو مُدرج في `.gitignore` ولا يدخل Git أبداً.
- توكنات Mapbox/Telr موجودة فيه كمدخل لـ `scripts/seed.py` وحده؛ المصدر الرسمي
  لها هو جدول `provider_credentials` المشفّر الذي يُدار من صفحة العقود.
- مزودو SMS وFCM وpayout وCliQ الآلي تُدخل عقودهم من اللوحة مباشرة — لا مكان
  لهم في البيئة إطلاقاً.

## ملاحظات معمارية

- **المصادقة عبر واجهة موحّدة** (`app/services/auth/`): `PasswordAuthStrategy`
  فعّالة الآن، و`OtpAuthStrategy` جاهزة كنقطة تبديل. `sms_provider_enabled()`
  تقرأ حالة عقد SMS من `provider_credentials`، فتفعيل العقد من اللوحة يحوّل كل
  المسارات إلى OTP دون تغيير أي endpoint (التنفيذ الفعلي في المرحلة 8).
- **عقود المزودين مشفّرة at rest**: العمود `credentials` مظروف JSONB
  `{"v": 1, "ciphertext": "…"}` بمفتاح Fernet. الحقول السرية تُقنّع (`****`) في
  اللوحة ولا تخرج من الخلفية؛ العام بطبيعته (Mapbox pk) يُسلَّم عبر `GET /config`.
  إعادة إرسال `****` تُبقي القيمة المخزّنة كما هي.
- **تفعيل المزود يفعّل ميزته** تلقائياً لدولة عقده (Telr → `card_enabled`،
  CliQ acquirer → `cliq_enabled`) — وتعطيله أو حذفه يعطّلها.
- **الهاتف مُعرّف الدخول** ويُخزَّن دائماً بصيغة E.164 بعد التطبيع
  (`+962…` / `+218…`)، فلا يمكن تسجيل نفس الرقم بصيغتين.
- **JWT**: access قصير العمر + refresh مسجّل في Redis مع تدوير لمرة واحدة —
  إعادة استخدام توكن مستهلَك مرفوضة، وتسجيل الخروج يُبطل الجلسة فوراً.
- **Rate limiting** على الدخول لكل رقم ولكل IP، وعلى التسجيل لكل IP، وعلى بثّ
  الموقع عبر REST لكل كبتن (30 في الدقيقة — دورة البثّ 3 ثوانٍ أي 20).
- **المال** كله `NUMERIC(12,3)` والعملة تُشتق من الدولة (LY→LYD، JO→JOD) في
  الخلفية — لا تُقبل من العميل.
- **سجل تدقيق** لكل إجراء إداري في `admin_audit_logs`، يسجّل أسماء الحقول
  المتغيّرة فقط ولا يسجّل أي قيمة سرية.
- **التسعير في الخلفية حصراً**: `POST /rides` يعيد حساب السعر ولا يقرأ أي مبلغ
  من العميل، و`commission_percent_at_ride` تُجمَّد لحظة الإنشاء.
- **التوزيع طلبٌ لكبتن واحد في كل مرة**: العرض محفوظ في Redis، فلا يقبل الرحلةَ
  إلا من عُرضت عليه وضمن مهلته، ومهمة التوزيع تُوقظها إشارة القبول أو الرفض.
- **مواقع الكباتن في Redis لا في القاعدة** (تتغير كل 3 ثوانٍ)، وحضورها بعمر
  محدود فيسقط الصامت تلقائياً من التوزيع والخريطة.
- **مقابس WebSocket بلا حالة في الذاكرة**: البث يمر بـ Redis pub/sub، فيعمل
  النظام بأكثر من عامل uvicorn. المصادقة عبر `?token=` لأن المتصفح لا يسمح
  بترويسات في مصافحة WebSocket.
- **سيارات خريطة الراكب مجهّلة**: إحداثيات واتجاه وفئة فقط، بمعرّف بديل يتغير
  مع كل اتصال (SPEC القسم 10).
- **انقطاع الكبتن أثناء الرحلة** أكثر من 60 ثانية يُنبَّه له الطرفان
  (`driver_connection_lost` ثم `driver_reconnected`) — ولا تُنهى الرحلة آلياً
  أبداً (SPEC القسم 5).
- Python 3.12 داخل الحاوية: أحدث إصدار تدعمه كل الاعتماديات الملزمة
  (asyncpg, SQLAlchemy 2, Celery) وفق قيد SPEC.

## الهوية الصوتية وقيدُ الوضع الصامت

نغماتُ التطبيقين مولَّدةٌ برمجياً بـWeb Audio من موتيفٍ واحد (`design/DESIGN.md` §9) — لا ملفاتِ
صوتٍ ولا شبكة. ولها مفاتيحُ **على الجهاز لا الحساب**: «أصوات التطبيق» و«صوت الإشعارات» في
الإعدادات، ويزيد تطبيقُ الكبتن مفتاحاً ثالثاً لـ«نغمة الطلب الوارد».

**وقيدان تقنيّان يُذكران ولا يُدَّعى خلافُهما:**

1. **الصوتُ لا يعمل قبل أوّل إيماءةٍ من المستخدم.** كلُّ المتصفحات تمنع تشغيلَ الصوت قبل لمسةٍ أو
   ضغطةِ مفتاح. ولذلك **توقيعُ العلامة يقع على أوّل لمسةٍ بعد الدخول** لا عند الإقلاع: نغمةٌ لا
   تُسمع في أوّل فتحةٍ هي الفتحةُ التي يُبنى فيها الانطباعُ الأول.

2. **مفتاحُ الصامت في iOS لا يوقف صوتَ الويب دائماً.** صوتُ `Web Audio` يمرّ بقناة الوسائط
   (media) لا بقناة النغمات (ringer)، ومفتاحُ الجانب يحكم الثانية. **لا حيلةَ في منصّة الويب
   تتجاوز ذلك** — ومن أراد ضماناً كاملاً فطريقُه تطبيقٌ أصيل (native) يعلن فئةَ صوته للنظام.
   فما نملكه هو مفاتيحُ التطبيق أعلاه، وهي المذكورةُ للمستخدم؛ ولا يُوعَد باحترامٍ لا نملك فرضَه.

## نفقُ Cloudflare — تجربةُ التطبيقات على هاتفٍ حقيقي (المرحلة 13)

بقيةُ المرحلة 13 — **كبتنٌ يتحرك وراكبٌ يطلب** — لا تُختبر على جهازٍ واحدٍ
بمتصفحين: الموقعُ الحقيقيُّ يحتاج هاتفاً يمشي، والمقبسُ يحتاج شبكةً حقيقية.
فالنفقُ يفتح الجهازَ المحلي على أربعة نطاقات، **والخلفيةُ تبقى في Docker محلياً**.

| النطاق | يصل إلى | المنفذ المحلي |
| --- | --- | --- |
| `app.tajora.ly` | تطبيق الراكب | 5176 (`CUSTOMER_APP_PORT`) |
| `driver.tajora.ly` | تطبيق الكبتن | 5174 |
| `admin.tajora.ly` | لوحة الإدارة | 5175 |
| `api.tajora.ly` | الخلفية | 8001 |

**ولا منفذَ محليٌّ تغيّر.** الملفّان الجديدان (`cloudflared/` و
`docker-compose.tunnel.yml`) **إضافةٌ لا استبدال**: بلا `-f` الثانية يبقى كلُّ
شيءٍ كما كان — نفسُ العناوين ونفسُ `VITE_API_BASE_URL: http://localhost:8001`.

### ما تفعله بيدك مرةً واحدة (خارج الكود)

1. **تثبيتُ `cloudflared`** على ويندوز: `winget install --id Cloudflare.cloudflared`
2. **الدخولُ بحسابك** — أنت لا الوكيل: `cloudflared tunnel login`
   يفتح المتصفحَ لتختار `tajora.ly`، ويكتب الشهادةَ في `%USERPROFILE%\.cloudflared\`.
3. **إنشاءُ النفق**: `cloudflared tunnel create taxo-dev`
   يطبع مُعرِّفَ النفق ومسارَ ملفِّ اعتماده. **انسخ المسارَ إلى
   `cloudflared/config.yml`** في سطر `credentials-file` (وسمِّ الملفَّ
   `taxo-dev.json` أو عدّل السطر ليطابق ما كُتب).
4. **ربطُ النطاقات الأربعة بالنفق** — أربعةُ أوامر، كلٌّ منها يكتب سجلَّ
   `CNAME` في Cloudflare:
   ```bash
   cloudflared tunnel route dns taxo-dev app.tajora.ly
   cloudflared tunnel route dns taxo-dev driver.tajora.ly
   cloudflared tunnel route dns taxo-dev admin.tajora.ly
   cloudflared tunnel route dns taxo-dev api.tajora.ly
   ```
5. **قيودُ URL لتوكن Mapbox العام** (لوحة Mapbox ← Access tokens ← التوكن
   العام ← URL restrictions): أضف النطاقات الأربعة
   `https://app.tajora.ly/*` و`https://driver.tajora.ly/*` و
   `https://admin.tajora.ly/*` (والرابعُ للاحتياط). **وبغيرها لا تُرسم خريطةٌ
   واحدة** والخطأُ يظهر في console المتصفح لا على الشاشة.
6. **Authorized domains في Firebase** (Console ← Authentication ← Settings ←
   Authorized domains): أضف `app.tajora.ly` و`driver.tajora.ly`. توثيقُ الهاتف
   يرفض أيَّ نطاقٍ غيرِ مُصرَّح، **ورسالتُه في المتصفح لا في التطبيق** —
   فتُقرأ «الرمز لا يصل» وهي رفضُ نطاق.

### التشغيل والإيقاف

**بـ`cloudflared` المثبَّت على ويندوز (الأبسط):**

```bash
docker compose --env-file .env.local -f docker-compose.yml -f docker-compose.tunnel.yml up -d
cloudflared tunnel --config cloudflared/config.yml run   # النفق في نافذةٍ أمامك
```

**و`--env-file .env.local` ليست زينة**: `env_file` في compose يغذّي **داخل**
الحاوية، أمّا `${CUSTOMER_APP_PORT}` في سطر المنافذ فاستبدالٌ يقرأ الصدفةَ
و`.env` وحدهما. وبدونها يرتدّ تطبيقُ الراكب إلى 5173 — المنفذِ الذي تشغله حزمةٌ
أخرى على هذا الجهاز — فيفشل الإنشاء بـ«port is already allocated». وقِيس.

الإيقاف: `Ctrl+C` في نافذة النفق، ثم `docker compose up -d` (بلا `-f` الثانية)
لإعادة التطبيقات إلى عناوينها المحلية.

**أو بالحاوية** (لا تُشغَّل مع الأولى معاً):

```bash
docker compose -f docker-compose.yml -f docker-compose.tunnel.yml up -d
docker compose -f docker-compose.yml -f docker-compose.tunnel.yml logs -f cloudflared
docker compose -f docker-compose.yml -f docker-compose.tunnel.yml stop cloudflared   # الإيقاف
```

**ولا `restart: unless-stopped` على النفق** عمداً: نفقٌ يعود وحدَه بعد إعادة
تشغيل الجهاز يعمل ليلاً بلا أن يعرف أحد.

### ⚠️ تنبيهٌ أمني — يُقرأ قبل التشغيل لا بعده

**النفقُ يفتح هذا النظامَ على الإنترنت فعلاً**، بقاعدة بياناتِ تطويرٍ فيها حسابُ
مشرفٍ بكلمة مرورٍ مكتوبةٍ في `CLAUDE.md`، وبمفاتيحِ مزوّدين مشفّرةٍ في القاعدة،
وبـ`environment: development` — أي مزوّدٌ وهميٌّ مسموحٌ به وحدودٌ أرخى.

- **يُغلق فورَ انتهاء التجربة**، ولا يُترك يعمل ليلاً ولا في الخلفية.
- **لا تُنشأ عليه حساباتٌ حقيقية** ولا يُدخَل رقمُ بطاقةٍ حقيقي.
- من يعرف النطاقَ يبلغ اللوحةَ وشاشةَ الدخول؛ الحمايةُ الوحيدةُ هي كلمةُ المرور،
  و**التحقّقُ الثنائي مطفأٌ في التطوير**. فإن طال التشغيلُ فأشعله (`/security`).
- وإن سُرّب شيءٌ فهو بيانات تطويرٍ لا عملاء — **ما دام لم يُستعمل حساباً حقيقياً**.

### ما ينكسر خلف HTTPS على نطاقٍ حقيقي — وما لا ينكسر

| الموضوع | الحال | لماذا |
| --- | --- | --- |
| **WebSocket** | **يعمل بلا تعديل** | `WS_URL` مشتقٌّ من عنوان الـAPI بـ`replace(/^http/, "ws")` في التطبيقين، فـ`https://api.tajora.ly` تصير `wss://…` وحدَها. و`cloudflared` يرقّي الاتصالَ تلقائياً. **ولولا هذا الاشتقاق لانكسر التتبّعُ كلُّه**: صفحةُ `https` لا تفتح `ws://` أبداً |
| **المحتوى المختلط** | **الخطرُ الأول** | أيُّ نداءٍ `http://` من صفحة `https` يحجبه المتصفحُ صامتاً. ولهذا `VITE_API_BASE_URL` تُبدَّل في طبقة النفق — ونسيانُها يعني تطبيقاً يفتح ولا يفعل شيئاً |
| **تحديد الموقع** | **يعمل — بل يلزمه HTTPS** | `geolocation` محجوبةٌ على `http` لغير `localhost`. فالنفقُ **يصلحه** لا يكسره: هاتفٌ على `http://192.168.x.x` لا يعطي موقعاً أصلاً |
| **عاملُ الخدمة** | يعمل، وقد يبقى قديماً | يُسجَّل في الإنتاج وحدَه (`import.meta.env.PROD`)، وخادمُ التطوير لا يبنيه — فلن ترى تخزيناً مؤقتاً هنا. وإن جرّبت بناءً حقيقياً: النطاقُ مصدرٌ جديد، والعاملُ القديمُ على `localhost` لا يخصّه. ولا يلمس `/api/` أصلاً |
| **Firebase Phone Auth** | **يحتاج إضافةَ النطاق** | reCAPTCHA يرفض نطاقاً غيرَ مُصرَّح — انظر الخطوة 6 أعلاه |
| **توكن Mapbox** | **يحتاج إضافةَ النطاق** | القيدُ على التوكن العام يُقاس بالنطاق — الخطوة 5 |
| **عودةُ صفحة البطاقة** | مضبوطةٌ في طبقة النفق | `CARD_RETURN_URL` و`CARD_RETURN_URL_DRIVER` و`PUBLIC_API_BASE_URL` تصير نطاقاتِ النفق، وإلا عاد الدافعُ من صفحة المزوّد إلى `localhost` — أي إلى الهاتف نفسِه |
| **CORS** | مضبوطٌ في طبقة النفق | `CORS_ORIGINS` تحمل النطاقاتِ الثلاثةَ **والمحليةَ معها**، فيبقى الفتحُ من الجهاز عاملاً بينما النفقُ قائم |
| **`Host` في Vite** | مضبوطٌ في الكود | `server.allowedHosts: [".tajora.ly"]` في الثلاثة — وبلاه يردّ خادمُ التطوير «Blocked request» بدل الصفحة |
| **HMR** | قد لا يتصل عبر النفق | لا يضرّ التجربة: أعد تحميلَ الصفحة بعد كلِّ تعديل. (ومع Docker على ويندوز لا يعمل HMR أصلاً — انظر «ملاحظات معمارية») |
| **بطءُ أوّل فتح** | ٤–٦ ثوانٍ، ثم عادي | خادمُ التطوير يرسل الوحداتِ مفرّقةً (٦٤ طلباً لشاشة الدخول)، وكلُّ واحدةٍ رحلةٌ عبر Cloudflare. مقيسٌ على هذا الجهاز — وليس عطلاً |
| **HMR عبر النفق** | يعمل | يفتح `wss://app.tajora.ly/?token=…` بنفسه (مقيس). ومع ذلك يبقى تعديلُ الملفات غيرَ مرئيٍّ من الحاوية على ويندوز، فأعد التشغيلَ كالمعتاد |
| **الكوكيز** | لا أثر | الجلسةُ توكنٌ في `localStorage` لا كوكي، فلا `SameSite` ولا `Secure` في الطريق |
